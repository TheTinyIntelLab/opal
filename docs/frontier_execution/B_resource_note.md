# B workload arithmetic before evaluation

This is analytical workload accounting, not a numerical profile. It follows B_proposal.md's initial menu and does not authorize numerical concurrency with root.

There are 96 cells times two budgets, hence 192 fitted procedures. The proposed fixed configurations comprise 16 simple references, one completion, two kernel and two neural models, hence 21 fits per procedure and 4,032 fits total. Three architecture-matched shuffles for each of the five residual configurations add 15 fits per procedure and 2,880 total, giving 6,912 fits before any extra diagnostics. This count does not treat a family-selected policy as another refit. A family-only shuffle design would be cheaper but must be stated prospectively instead of called configuration-matched.

With the proposed fixed optimizers, original plus three shuffled completion copies require 384,000 Adam steps. Two neural penalties and their three shuffled copies require 460,800 steps. The combined 844,800 steps, reference solves, kernel eigendecompositions, all prediction serialization, sensitivity arithmetic and installed replay belong in the forecast. Passing one easy fit within 600 seconds says little about the full 7,200-second program.

Storing every model's float64 predictions for both initiations on all 1,770 pairs costs 195,747,840 bytes for 6,912 fits, before input arrays, checkpoints and manifests. Storing only the 531 TEST pairs for both initiations costs 58,724,352 bytes, but validation predictions, declared scoring populations and required replay still need explicit custody. Saving duplicate per-configuration inputs or dense matrices could exhaust the 256 MiB artifact budget. Share immutable input objects by hash, persist compact sufficient checkpoint state, and measure actual full-cell serialization and disk growth in root's pilot. Do not silently omit losing configurations or shuffled controls after seeing scores.

If root's final roster differs, recompute these counts from the frozen machine-readable menu. B's proposal is not a passed resource qualification; D's independent resource objections and root's measured forecast decide feasibility before evaluation generation.
