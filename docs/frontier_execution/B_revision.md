## Feature parity

Accept D's objection. C's independent two-dimensional synthetic gene features are available inputs only inside the registered synthetic task. Use standardized x_i=[single_i,z_i0,z_i1] there. In any later no-feature biological task, x contains only the measured single and the model/schema is registered separately. No synthetic z, oracle factor, graph or pretrained embedding is transferred into biology.

For this synthetic feature track, add the following eight columns to every B1/B2/B3 design: for each of z0,z1, the pair sums of z, z squared, sin(z) and cos(z). Fit their moments on selected usable TRAIN and use the same stated penalty as other nonconstant columns. This introduces no new configuration. B2/B3 gene incidence can also represent arbitrary additive per-gene feature effects on supported genes. Feature-independent B0 remains fixed. B3's 64-center nonlinear pair map still uses sorted singles; it is now accompanied by a declared additive-feature reference, not mislabeled a fully flexible multivariate feature map.

I1 uses k(i,u)=0.5*delta(i,u)+0.5*exp(-||x_i-x_u||^2/2), retaining the same symmetric tensor construction and two penalties. I2 adds an affine feature projection W*x_i to embedding e_i before its shared transform. W has shape 4 by dim(x), uses the same initialization and penalty, and has no projection bias. This gives both interaction families explicit access to C's supplied z while the references receive the matching additive features. Sharing a feature array that a candidate ignores is insufficient parity.

The structured nonlinear world tests composition of available synthetic features, not a graph model or evidence that biological features are available. For guide/arm/batch effects, accept C's requirement to retain the four-construct tensor and nuisance metadata. Root must either implement a shared TRAIN-fitted nuisance adjustment and construct-level scoring, or prospectively label that world an unmodeled-nuisance falsification control and omit nuisance-recovery claims. B does not invent unspecified guide designs to close this objection. This remains a root freeze decision.

## Exact new numerical recipes

The rank-eight comparator is a newly named one-context signed completion reference. Let U,V each be n_genes by 4 and R_ij=U_i dot U_j - V_i dot V_j. Initialize both from N(0,0.05) on one frozen optimizer stream. Optimize mean TRAIN residual squared error +0.001*(sum(U squared)+sum(V squared))/n_genes using 500 full-batch Adam updates, float64, learning rate 0.03, betas 0.9/0.999, epsilon 1e-8, weight_decay=0, amsgrad=False, no clipping, no scheduler. Take update 500 with no validation checkpoint choice. This is not a claim that these settings reproduce the two-context historical fitter, and root must retain that historical reference's documentation/checkpoints unchanged. A separate historical source-local adapter may be documented but cannot ingest initiation two for this tournament.

For I2, define a_i=e_i+W*x_i; h_i=L2(ReLU(L1(a_i))), with L1 4-to-8 and L2 8-to-4, each with bias. Then c_ij=concat(h_i+h_j,h_i*h_j), and correction=L4(ReLU(L3(c_ij))), with L3 8-to-16 and L4 16-to-1, both biased. No output activation. Every linear weight uses Xavier uniform gain 1, all biases zero, gene embeddings N(0,0.05). Penalize sum of squares of ALL scalar trainable parameters divided by their total scalar count, using lambda 0.001 or 0.01. Use mean TRAIN residual MSE, 300 full-batch Adam updates, learning rate 0.01, and the same Adam betas/epsilon/flags as completion. Take update 300. Frozen seed streams include identity initialization, feature weights and layer weights; fit order must not alter them. Symmetry follows sum/product composition. Save trained parameters for inference replay, not a promise of optimizer retraining invariance.

For B3, use min(64,n_observed_train) distinct canonical TRAIN pair centers in stable SHA256 order, not unique coordinate values. Repeated coordinates are legal duplicate columns; ridge handles rank deficiency. Bandwidth is median of strictly positive Euclidean distances among sorted-single TRAIN coordinates, computed once; if none exist, set bandwidth to 1. RBF is exp(-distance_squared/(2*bandwidth squared)). A zero-range feature has standardized value zero and stored scale 1. All feature-column centers/scales use TRAIN, and zero-variance design columns become zero. Intercept is unpenalized, while all other columns share sum-loss ridge lambda. Empty usable TRAIN or VALIDATION is a declared invalid cell, not a tuned recovery case. This is a new bounded reference, not a change to historical FlexibleSingles.

For I1, landmarks are min(64,n_observed_train) canonical TRAIN pairs ordered by SHA256 of the UTF-8 string 'frontier-landmark-v1|' plus canonical integer endpoints separated by '|'. Use the first such rows. Freeze base x scaling on unique TRAIN-supported genes, with zero SD replaced by 1. Symmetrize W numerically as (W+W.T)/2, use float64 eigh, and reject eigenvalues below -1e-8. Set smaller negative roundoff eigenvalues to zero and retain eigenvalues strictly above absolute 1e-10. Save the fitted eigenbasis and eigenvalues rather than recomputing them on load. Center/scale Nyström columns on TRAIN, store moments, fit a residual intercept and sum-loss ridge lambda 10 or 100. If no basis remains, fit only the residual intercept. Roundoff PSD handling and repeated eigenvectors are pinned-stack inference contracts, not cross-platform reconstruction claims.

## Support and total fallback

Accept D's fallback objection. Separately select and save the strongest singles-only B0/B1/B3-without-gene design, excluding synthetic feature columns for this fallback, using the same charged VALIDATION outcomes. This auxiliary selector adds no labels but does add declared fits if root cannot share existing compatible fits; freeze and profile those counts. Its role is fallback, not an unreported extra interaction competitor. Root can instead choose fixed raw single sum to avoid extra fits, but must decide before evaluation.

Primary full-population predictions use the candidate when both endpoints have finite measured singles and at least two distinct observed TRAIN partners, otherwise use the saved singles-only fallback. If a required metadata feature is missing for a supported pair, fall back rather than impute a hidden oracle value. If either single is absent, use saved TRAIN target mean. Fallback is a total function for finite queries, and missing schema/invalid identity still raises a contract error. Report candidate support, fallback reason, full-population loss and the common-supported subset separately. An unsupported gene does not get an untrained embedding or zero-valued coefficient as a claimed model prediction.

## Shuffles and selection

Use three pair-residual shuffles, seeds 2026102601, 2026102602, 2026102603, reserved independently of data/optimizer seeds. Before labels, bin TRAIN pairs by whether minimum endpoint TRAIN degree is below or above its TRAIN median and whether standardized single sum is below or above its TRAIN median. Exact-median ties go above. Freeze these four strata. Within each stratum, hash-order pair identities and apply a seed-selected nonzero cyclic offset when size is at least two. Singleton strata remain fixed. Require at least 80% of selected observed TRAIN residuals to move; otherwise the cell fails shuffle qualification and cannot support a positive shuffle-superiority claim. Never adjust bins after seeing the fraction or outcomes. Construct measurements stay grouped by pair.

Refit every one of the five interaction configurations on each shuffled residual vector and select within each shuffled family by VALIDATION using original validation targets and shared main effects. Also select a shuffled full interaction policy with the same family/complexity rule. Report the matched family and shuffled-policy scores; do not select the easiest null. Preserve the shared reference and input moments. There are no additional optimization restarts. Save all configurations and count every shuffle fit in the resource ledger.

The original B menu's 21 main plus 15 shuffled configurations gives 6,912 fits across 192 procedures, as B_resource_note.md records. This revision's feature columns do not add configurations, but a separately fitted singles-only fallback would increase this count and must be forecast explicitly. A fixed-sum fallback avoids that extra count. D's criticism is accepted; no full-run feasibility claim follows from arithmetic alone.
