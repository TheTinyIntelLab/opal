# Root response to independent result review

Root reviewed the full [Grok result audit](Grok_results_review.md). Its checks agree with the failed program result and the exact staged/live aggregate hash. No finding changes the stored scores, selection or Jurkat's failed5% criterion. No model, split, gate, checkpoint or frozen receipt is edited in this response.

The dependence critique is accepted. K562/Jurkat share a pair partition and differ in phenotype and selected-simple denominator. Environment tasks share an accession salt; the reviewer did not compare their pair arrays. PARP banks belong to one accession family. Cross-fold TRAIN/VALIDATION labels can overlap even though pooled TEST blocks are disjoint. Six task rows and thirty fits cannot be presented as independent replications. Pooled equal-pair MSE also gives larger blocks more weight, and the current ledger does not supply per-block test losses. Leave-one-gene sensitivity does not replace a block sensitivity analysis.

The selection critique is accepted. Completion chooses its checkpoint on the same charged VALIDATION set used for family selection, while the small network uses a fixed update count. This was frozen before evaluation and does not expose TEST targets to the selector, but validation ranking is optimistic and the optimization opportunities differ. The supported claim is performance of these exact registered procedures on these exposed tasks, not a capacity-matched or universal architectural superiority result. No post-outcome optimizer changes or retrospective checkpoint menu are introduced.

The metadata critique is accepted. `bank-expectations.json` and packing-qualification fields describe pre-fit snapshots. Their `banks_opened: false` and `biological_fits: 0` values are not the finished run's exposure state. A separate run-closeout receipt explicitly records that the six qualified historical banks were subsequently loaded and all30 fits scored; original snapshots remain byte-exact. This run has a reviewed qualification stamp, bound by the fit watchdog. The v3 CLI checks qualification but does not itself require that manual review stamp. It must not be advertised as an automatic review-authorization barrier.

The support critique is accepted as a future-interface constraint. Every model in this frozen menu uses the same two-partner support rule and every test row was supported, so using one saved mask cannot change these results. The loader replay checks predictions, not a separately compared support vector. A future family with different abstention support requires per-model masks and replay assertions under a new contract before fitting. Frozen v3 is preserved rather than silently patched after results.

Root accepts the review's limits. The next experiment needs a new scientific question and qualified evidence, not rescue of this failed gate. The source qualification and exposure ledger remain binding. Reporting-only root arithmetic checks are separately labeled and do not stand in for the independent code/aggregate review or a response-level independent reproduction.
