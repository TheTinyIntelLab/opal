# Frontier candidate model contract

`opal.frontier_tournament` is a separately versioned research API for pair prediction among genes with observed singles and local pair supervision. It preserves the historical flexible-single predictor, evaluators, checkpoints and failed compatibility gate. It is not a universal virtual-cell model, a biological-interaction identifier or an established frontier model.

The shared menu contains16 fixed/calibrated/gene-main/flexible references, source-local completion, an identity/single symmetric tensor kernel and a small regularized symmetric composition network. Every interaction fits residuals from the same saved validation-selected simple reference. The finite grids, steps, seeds, preprocessing and information budgets are in the registration; no model receives latent generator features or global pair outcomes.

The kernel mixes an identity kernel with an RBF on standardized measured singles, then symmetrizes their tensor product. Its identity-by-single terms permit a gene's partner-response curve to vary with its partner's single effect, which an additive gene term plus smooth singles map cannot generally express. It uses64 TRAIN landmarks and two ridge penalties. The network uses4-dimensional gene embeddings, a shared encoder and an order-invariant sum/product head, with300 fixed updates and two regularization values. It is NAIAD-like, not a native NAIAD reproduction. The completion reference reuses the unchanged one-context scalar adapter rather than fabricating a second context.

`fit_models` accepts singles, a feature array exactly equal to the single column, selected TRAIN pairs/labels and selected VALIDATION pairs/labels. TEST targets and second-initiation targets are not inputs. Extra features, reversed canonical overlap, duplicate fitting pairs, nonfinite inputs and invalid identities are refused. New biological tasks need a separate source/endpoint/budget registration; the module itself grants no response access.

`Predictor.predict` requires both query genes to have at least two distinct observed TRAIN partners. The registered policy uses fixed measured-single sum for unsupported queries and reports coverage. It cannot detect an unobserved technical shift when the measured inputs look unchanged. The VALIDATION absolute-error radius is diagnostic only and cannot certify arbitrary OOD coverage.

Checkpoints use `opal-frontier-synthetic-v1`, non-pickle arrays, explicit shapes and optional expected SHA256. This name identifies the prospective numerical format, not a biological-use authorization. Save/load replay is exact for the recorded query vectors on the pinned stack; no historical compatibility, universal batching invariance or arbitrary-range accuracy is claimed. Source-local gene names and schemas must accompany any biological use of the integer-pair interface. A checkpoint without its schema and source contract does not support arbitrary gene symbols.

The [complete synthetic results](synthetic_results.md) show complementary recovery and substantial failures. Completion wins on persistent low-rank structure at the larger budget; the composition network wins on the structured partner-curve slice, while its smaller-budget performance is poor. This evidence justifies testing the finite menu on an independently registered qualified source, not promoting one architecture from a favorable simulator.

The completed [exposed-growth comparison](growth_results.md) selected completion in every fold. The kernel did not provide a substantial gain over the strong single-effect references, and the small network did not beat completion. Jurkat missed the unchanged5% threshold, so no all-task model is promoted. New codecs `opal-frontier-packing-v1` and `opal-frontier-packing-v2` preserve float64 checkpoint bits through upper-triangle storage and reversible byte-plane shuffling; their strict loader reconstructs the original prediction contract before replay. Biological weights remain local under the original source restrictions.
