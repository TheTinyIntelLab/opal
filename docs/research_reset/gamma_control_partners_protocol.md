# Q1b control-partner identity sidecar

This separately registered, no-fit identity audit supplements the frozen Q1b gamma analysis. It records which explicitly named metadata controls support each exact guide, arm, context and infection. It performs no loss calculation, model fitting, eligibility change or tuning and cannot establish why a control is absent. Existing Q1b and Q2b gates are unchanged.

Bind the completed Q1b registration, results, passing replay and prepared NPZ, plus the phenotype and library gzip hashes. Reuse the unchanged Q1b header/guide/duplicate validation parser. From the 18 sorted explicitly named metadata controls, assign one uint32 bit per control. For each target/control ordered construct, set that control bit in its target guide's exact arm/context/infection cell if the selected processed gamma field is finite. Record separately whether each metadata control occurs in any source construct, even where outcomes are unavailable or the partner is another control. Repeated ordered guide/control constructs are rejected by the frozen parser. No identity substitutions or invented transcript/mismatch annotations are allowed.

Output arrays have shape context, infection, arm, guide and retain ordered guide names, sorted control names, finite-partner bitsets, popcounts and observed-source-identity flags. Every cell's population count must exactly equal the Q1b prepared `guide_single_counts` after explicit axis transposition. Fail on any mismatch, drift or ambiguity. Report each control's source presence and finite target-single cell count, controls absent from every source construct and controls observed but never finite as single partners. Absence can describe the deposited table only; it does not identify a biological or upstream filtering mechanism.

Synthetic qualification must pass after freezing and before the full stream. Tests cover exact control identity, arms, contexts, infections, unavailable versus finite zero fields, absence versus nonfinite support, duplicate guide/control rejection, exact count reconstruction, frozen input drift, no-overwrite lifecycle, replay corruption and resource caps. Store immutable registration, JUnit/log hashes, starts and failure records. Require exact array and JSON replay, preserving every failed attempt. Never overwrite or automatically retry a started attempt.

Use one numerical thread, at most 180 cumulative run-plus-replay CPU and wall seconds, peak process working set/RSS 256 MiB, sidecar artifacts 5 MiB and 1 GiB free-disk reserve. Boundary process guards enforce these declarations; they are not OS hard limits. Registration/input hashing and synthetic qualification are administrative work outside that scientific budget. The source is the already exposed GSE116198 asset; SPIDR responses remain closed. Input arrays and source assets remain outside Git. Only compact scientific metadata and receipts may be committed, with the historical provenance/licensing caveats retained.
