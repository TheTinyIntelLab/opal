The separately frozen [tail diagnostic](padded_tail_diagnostic_v1.md) executed 1,008 contraction configurations and 3,024 selected-query observations over three actual validation kernels, with synthetic zero/repeated fillers. Of those, 1,818 whitening vectors matched their original reference bitwise; maximum discrepancy was 3.368635837435728e-11. At one thread with C operands, the final query in trailing position reproduced its original whitening for every tested odd row count at least three; even counts differed by 3.045525368217594e-11, and a singleton differed by 2.546585164964199e-11. Two threads gave explicit exceptions at row counts 129, 1443, 1444 and 2049. This challenges a universal parity rule. Singleton Fortran operands gave distinct vectors; zero/repeat fillers gave identical vectors at each fixed thread/shape/position/layout/query. No particular microkernel is proven without implementation tracing.

The `math.fsum` oracle sums float64-rounded products; it is not exact unrounded matrix multiplication. The three original reference rows differed from it by maxima 2.4714120165887516e-11, 2.0050608065280564e-11 and 2.883837613154583e-11. Consequently reference compatibility and arithmetic accuracy remain separate questions. Decision: preserve the historical predictor, both failed protocols and the separate fixed-order opt-in contract. Do not add a padding API or exempt the final row. An adapter tied to an entire fixed query schedule would change its interface and could not be presented as a universal pointwise repair. A future scientific fit still requires independently reviewed numerical/evaluator contracts and qualified actual source metadata, with a new registration.
