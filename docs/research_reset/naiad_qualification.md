# Native NAIAD software and resource qualification

The native comparator runs successfully with supplied splits and numerical checkpoint replay. This qualifies software compatibility, not biological performance or a completed NAIAD benchmark. No biological fit or SPIDR response access occurred in this branch.

The adapter imports official NeptuneBio/NAIAD revision `9207e9e855e865160a196a6989392f6db622b0d6` after checking HEAD and all five Python-file SHA256 values. The source is Apache 2.0 and remains in the external checkout `C:/Users/USER/Desktop/opal-research-next-20261020/NAIAD`. Dependencies were already installed. No new GPU or package installation was needed. Python 3.14.0 and exact package versions are recorded in each registration.

Three synthetic prerequisite tests passed in 3.21 seconds for v1. They exercise input-integrity failures, no native random resplit, test-outcome sentinel invariance, deterministic training, validation-only checkpoint choice, exact numerical replay, pickle-free state, tamper refusal and batch-level interruption. Native integration tests are optional and explicitly skip if the pinned checkout is absent. The native scheduler warns about rounding a fractional warmup count in small test cases; its behavior is preserved.

V1 used 512 synthetic genes and 81,466 pairs, with 65,172 train and 12,220 validation rows. The official 100-epoch default recipe took **132.26603229999455 seconds** to fit and **132.358487599995 seconds** including prediction/export/replay. Forward-boundary sampled peak RSS was **487,116,800 bytes**. The model had **198,275 parameters**, native dimensions 128/256 and validation-selected epoch 98. Safe loaded predictions matched exactly. Thirty copies of this measured fit extrapolate to **3,967.9809689998365 seconds**, failing the conservative one-hour screening estimate. This is a runtime projection, not 30 completed fits. Per-batch/epoch timing was not instrumented; dividing fit time by 100 gives 1.32266 seconds per epoch including setup and validation, not a measured median.

The v1 workload initially represented the known Horlbeck bank. Read-only roster qualification then showed larger full external prepared banks, including PARPi 2022 with 144,601 pairs. V1 therefore remains a smaller-workload receipt. Its original driver is retained at `results/research-reset-naiad-qualification/v1/qualify_naiad_frozen.py`; the source architecture and wrapper were unchanged. A separately registered v2 profile uses 600 synthetic genes and 144,601 pairs before any biological fitting. Its receipt determines whether a justified new resource registration can retain the same native recipe. No width, seed, learning-rate or epoch rescue follows biological outcomes.

V2 completed the same 100-epoch native recipe on 115,680 train and 21,690 validation rows in **232.33605510000052 seconds** to fit and **232.48638349999965 seconds** including export/replay. Sampled peak RSS was **503,033,856 bytes** and the model had **209,539 parameters**. Validation selected epoch 99 and safe replay was exact. Thirty largest-workload fits extrapolate to **6,970.081653000016 seconds**, failing the original one-hour screening estimate but fitting below a proposed two-hour native-only cap. Actual six-task/five-fold row counts support a smaller weighted estimate, recorded in `results/research-reset-naiad-qualification/resource_amendment.json`. The parent must register a justified new limit before biological fitting. No native biological benchmark is completed here.

The frozen actual thirty-fold train/validation counts give a row-scaled estimate of **4,449.085773714356 seconds** and a minibatch-scaled estimate of **4,481.504351706677 seconds**. Taking the larger estimate, adding 25% and two seconds of setup per fit gives **5,661.880439633346 seconds**, below the proposed 7,200-second native-only cap with the same 2 GiB/one-thread constraints. These workload projections use counts, not biological responses. The proposed amendment preserves the original one-hour failure and changes only the prospective resource allocation. A real cap overrun must leave an incomplete roster, with no silently shortened training or selected subset.

The final adapter adds a seed-fixed training-only row permutation, accepts missing singles for unqueried genes without imputation, and pins normalized-LF native Git-blob hashes so Windows CRLF checkout remains portable. These prebiology fixes passed four synthetic tests. V2's exact pre-fix adapter, driver, tests and protocol are retained in its `frozen` directory with matching profile hashes. Final code/test receipts are separate. Architecture, trainer, optimizer, dimensions and number of operations are unchanged; runtime is carried forward as an estimate rather than misreported as a second profile of the final wrapper. Source/metadata preparation briefly overlapped profiling, but no competing biological or other CPU model fit occurred.

The exact frozen native recipe and limitations are in [the protocol](naiad_protocol.md). The official dataset independently shuffles the two single-phenotype columns with its fixed seed zero. The adapter preserves native training but averages both phenotype orders at inference, so report "native NAIAD architecture/trainer with symmetric inference". Native train/validation loss does not use this prediction averaging. This is a declared evaluation adaptation and cannot be described as an exact published-score reproduction. No unsupported gene embeddings are queried, and no cold-gene capability is claimed.

They were never opened, parsed or scored, and the checkout was immediately restricted to source/README/license/dependency metadata. The external directory including Git object cache occupied **18,307,114 bytes** at v1 completion, below the 100 MB acquisition cap. Cached acquisition is recorded, rather than described as absence of bytes. No biological data or native source was added to Opal.
