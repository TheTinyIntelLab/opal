# Native NAIAD qualification and common-split comparator

This registration covers Q3 software qualification before any new biological fitting. It uses official NeptuneBio/NAIAD revision `9207e9e855e865160a196a6989392f6db622b0d6`, Apache License 2.0, outside this repository. The wrapper imports the official architecture, dataset, optimizer, scheduler and trainer. No architecture is copied. It is a native model/trainer comparator with an explicit symmetric inference adapter, not a reproduction of a published numerical score.

Official references are the [pinned source](https://github.com/NeptuneBio/NAIAD/tree/9207e9e855e865160a196a6989392f6db622b0d6), [model/trainer](https://github.com/NeptuneBio/NAIAD/blob/9207e9e855e865160a196a6989392f6db622b0d6/naiad/naiad.py), [tutorial](https://github.com/NeptuneBio/NAIAD/blob/9207e9e855e865160a196a6989392f6db622b0d6/tutorials/naiad_tutorial.ipynb) and [license](https://github.com/NeptuneBio/NAIAD/blob/9207e9e855e865160a196a6989392f6db622b0d6/LICENSE). The tutorial's primary model uses 100 epochs and `initialize_model`/`setup_trainer` defaults. This qualification freezes those choices without biological scores.

## Frozen recipe

Use seed 20261022, 100 epochs, batch size 1024, one CPU thread and CPU float32. Preserve `initialize_model` defaults, including `model_type=both`, MLP embedding branch, dropout .1, phenotype hidden dimension 256, and the native embedding-size lookup based only on training row count divided by treatment count. The map is 2/4/16/16/32/64/64/128/128 at thresholds 0/2/4/10/20/30/40/60/80/100, with the native strict-lower-threshold rule. Preserve native Adam, learning rates .01 for both branches, zero weight decay, summed MSE and the native ten-percent-warmup learning-rate scheduler. Do not rescale targets or replace the loss.

Use the shared Q2 block splits and identical eligible pairs, measured local singles and mean-replicate target. Construct native input frames from TRAIN and VALIDATION only. Apply one `np.random.default_rng(20261022).permutation` to original training row indices before constructing the frame, keeping validation order fixed. Record actual original-row IDs in their fitting order. This preserves the native initial training-row shuffle without changing supplied memberships. Held-test labels may be NaN and must never be inspected or passed to the native runner. Do not call native `prepare_data`, which randomly resplits. Inject `runner.data` with only train and val, then call native `prepare_dataloaders`. Its constructor insists on positive test counts, so initialize an inert `n_test=2` against train+val rows and immediately reconcile `n_test=0,n_val=len(val)` before loaders or model creation. No placeholder biological test label or test identity enters this object. Training count remains exact throughout and determines native capacity. Require at least two train and three validation rows. Require finite singles for every queried gene, while preserving unavailable singles for unused genes as unavailable rather than imputing them.

Keep native phenotype-column shuffling, which uses a fixed dataset-local generator seed zero. The native phenotype head is order-sensitive, so inference averages native outputs for the two orders of the same measured singles. The embedding branch is symmetric. This averaging is fixed before biology, uses no labels, and prevents arbitrary canonical-name order from changing a symmetric gene-pair prediction. Report it as an inference adaptation. All lookup genes need incident training pairs. This comparator cannot support cold-gene claims.

Run every native epoch and use the official `best_model`, the first strict minimum validation-MSE checkpoint. Record the complete train and validation trajectories, selected epoch, model arguments, parameter count, train/validation row indices and file signatures. No test loss is computed during fitting. Native `save_results` uses pickle and is not called. Save only numerical/string NumPy arrays with `allow_pickle=False` replay and JSON metadata plus SHA256 integrity. Checkpoint metadata is an integrity receipt, not an authenticity signature.

## Tests, resources and decisions

Before the synthetic profile, tests must reject missing train/validation outcomes, missing singles, duplicate pairs and unsupported genes; prohibit hidden random resplitting; replace held-test outcomes with NaN and require identical fitted state/selection/predictions; verify deterministic replay, validation-only checkpoint choice, numerical serialization, tamper refusal and resource-interruption callbacks. Native-only tests skip when the optional pinned checkout is unavailable and must be reported as skipped in that environment.

The maximum-size synthetic profile has 600 genes and 144,601 pairs with 115,680 training, 21,690 validation and 7,231 withheld pairs. This conservatively covers the largest registered bank and exercises the native maximum embedding size. Its finite, deterministic artificial target is not biological evidence. A preliminary v1 profile used 512 genes and 81,466 pairs, before full prepared external-bank metadata showed that the largest task was bigger. V1 remains a valid measured smaller workload, not the claimed largest task. Its runner is preserved beside its receipt. The v2 prefit registration records updated source/code/dependency hashes. Cap either profile at five minutes and 2 GiB resident memory, checked on every native forward call. A forward pre-hook calls the parent's guard during every training and validation batch, and hooks are removed from selected checkpoints before inference/export. One operation between checks is not an OS-enforced hard memory limit.

The original screen required thirty times measured fit runtime to be at most one hour. Both profiles failed that conservative screen, and it remains recorded as a failure of the original resource estimate. A prebiology resource amendment may use the frozen actual thirty-fold row counts to justify a new total limit without changing native capacity or epochs. Any such limit needs its own recorded registration and a shared wall/RSS guard. These extrapolations are estimates, not completed benchmarks. Stop rather than silently shorten native training. Reducing epochs/width after biological results is prohibited. Q2 may still proceed without a qualified native comparator, but cannot claim superiority to native NAIAD.
