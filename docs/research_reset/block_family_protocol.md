# One exploratory validation-selected family policy

This registration was proposed after Q2 test results were exposed and before any native NAIAD or family-selector test scoring. It is partly post-Q2 development, not untouched confirmation. It changes neither the Q2/Q3 gates nor model promotion. Run this one selector only; there are no threshold, margin, seed or family-menu variants to choose after its results.

Freeze with `tools/select_block_family.py freeze --block-run C:/Users/USER/Desktop/opal-research-next-20261020/block-v2 --native-run E:/opal-research-next-20261021/native-block-v6 --output E:/opal-research-next-20261021/family-v1`, then run `verify` against that output before `select`. Freeze binds code, dependencies, original splits, Q2 results and the immutable native protocol, inheritance manifest, prerequisites and run-start receipt. Native fitting may still be running. This driver never fits a model or changes any ongoing native file or runtime code signature.

Selection requires all thirty completed native checkpoint selections and all thirty Q2 selections. Before reading validation targets, bind those manifests and every declared checkpoint by SHA256. Require original recovery custody and matching source data, dependencies and split assignments. Refuse native `score_started.json`, `results.json` or `replay.json` until every family choice is finalized. All six tasks and all five folds remain mandatory.

For each task/fold, recompute predictions on exactly the shared validation indices for three stored procedures: Q2's validation-selected simple policy, that policy plus its fixed aligned rank-eight residual, and the stored native NAIAD checkpoint with its fixed symmetric inference API. Do not change the native checkpoint using symmetric validation predictions. Choose minimum equal-pair validation MSE. Exact ties prefer simple, then rank8, then native. Do not use a gain margin or test labels to select. Save all thirty choices, all three validation losses, validation-index and prediction-array hashes, and the complete checkpoint binding before any native or selector test scoring. The loader reads the source bank, but only explicit validation rows enter choice calculations.

Once choices are final, the original native test scoring and exact replay must finish. The family `score` command then combines the already frozen Q2 and native test prediction arrays according to those choices. Require identical canonical-pair index order and exact shared-fold membership; no model retraining, checkpoint replacement or new prediction tuning occurs. Report each task separately with equal canonical-pair weights: MSE, MAE, signed bias, centered Pearson and target variance; paired comparisons against each fixed family; both infection targets; family frequency by folds and pairs; and all fixed-family metrics. Report per-fold empirical test-best family and regret only as failure diagnostics, never as replacement choices.

Use 2,000 endpoint-multiplicity gene draws with seed 20261022 and leave-one-gene-out influence through the original paired comparison implementation. These are conditional sensitivity bounds, not independent-culture confidence intervals. No result changes the Q2/Q3 gates or constitutes independent source confirmation. The selector can diagnose whether validation identifies useful differences among fixed procedures on exposed sources.

Replay combines the identical fixed predictions using the hash-bound choices, checks saved arrays exactly and requires identical scientific JSON. Require postfreeze synthetic tests for exact tie order, test-label sentinel invariance, all thirty choices before scoring, missing/duplicate selections, checkpoint tampering, array alignment, and deterministic replay. Partial attempts, failures and replay mismatches are preserved under their experiment ID.

The resource guard allows one CPU numerical thread, 600 seconds summed active selection/scoring/replay wall and CPU time, 2 GiB process memory, 128 MiB artifacts and at least 1 GiB free writable volume. Carry consumed selection resources into scoring and replay. The original guard checks sampled/OS-reported peak memory and writable space at numerical boundaries, rather than enforcing a kernel memory limit. Stop on a cap or custody failure. No source count acquisition or SPIDR response access is part of this experiment.
