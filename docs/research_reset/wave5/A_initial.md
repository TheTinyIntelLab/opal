## Hypotheses and contracts

H1: v1 saved-state replay reproduces 1.2463305998355878e-8 without fitting. Its incidence-last layout and changed accumulation leave fitted-state differences as well as map-evaluation differences; a causal attribution must separate those components rather than borrow v2's conclusion. H2: v2 reproduces 1.245199382493567e-8, with the first prediction-path difference at kernel-whitener multiplication and amplification through small frozen feature scales. H3: fixed-order per-row contractions can improve caller invariance while disagreeing with the immutable legacy vector. H4: dtype, layout and thread changes can alter low-order bits; repeatability within one environment does not establish cross-platform identity.

Legacy compatibility is against Q2b's selected saved state on the original ordered 15,779 validation queries with historical internal chunk 2048, atol=1e-12 and rtol=0. This target is never regenerated using a preferred candidate or another chunk schedule. A prospective invariant contract compares each candidate against itself after caller partition, inverse permutation, repeated-row, orientation and layout changes. Exact equality and the unchanged absolute gate are both reported; passing one contract never implies passing the other. Disagreement among legacy schedules cannot prove that no invariant function matches the single immutable target. No scientific fit or successor is authorized.
