## Accepted review changes

1. **Two independent reproductions.** A1 writes distinct v1/v2 expected and observed maxima, error against the registered maximum, and reproduced/incomplete/failed statuses. V1 uses its own saved transform and selected baseline. Canonical column order is sum/absolute difference/product, gene incidence, nonlinear map. Map, state, projection and assembly substitutions remain separately labeled. Missing v1 state records blocked reproduction and cannot trigger refitting.

2. **Target provenance.** The comparison target is Q2b's selected saved checkpoint evaluated on the immutable ordered fold-zero validation sequence, with the predictor's internal query-local chunks of 2048. Global-bank chunks of 2048 define the stopped nuisance mapping path, not the target. The historical records inspected so far identify the saved checkpoint, keys and schedule but not a separately saved validation-prediction vector. If no permitted pre-existing vector is registered, the report must say reconstructed historical-schedule target and record its digest, state/input hashes and exact reproduction against wave-four diagnostics. It must never imply an independently archived prediction vector was loaded. No test vector, response array or validation loss is read or recalculated. Different candidate schedules never replace this target.

3. **Stage-specific arithmetic controls.** Float64/thread=1 is primary. np.matmul and @ provide an equivalence control. Einsum optimize=False, einsum optimize=True and fixed ascending reduction each run whitening-only, final-projection-only and joint substitutions. The fixed reduction multiplies float64 operands, rounds each product to float64, then adds in increasing center/feature index to a float64 accumulator using row-elementwise operations. It is a declared arithmetic procedure, not proof of mathematical accuracy. Its own partition/order/repeat/layout controls run even if compatibility fails. Optimized einsum receives no presumption of invariance.

4. **Conditioning attribution.** Signed weighted deltas, abs-weight triangle bound, actual scales, coefficients, floor-contact flags and final residual use the same implicated row. A reported scale amplification is not evidence that floor clipping caused the failure. V2 identical saved coefficients distinguish evaluation sensitivity from fit conditioning. V1's state differences require their own evidence. No normal-equation solve or fit is run. Longdouble support and np.finfo mantissa width are recorded; a format equal to binary64 is reported as providing no extra precision. Float32 and longdouble never change the compatibility gate or historical state.

5. **Separate contract records.** Each arithmetic candidate has legacy compatibility and prospective self-invariance fields, each containing bitwise equality and atol=1e-12/rtol=0 verdicts. Relative errors are descriptive, with zero-reference exceptions counted separately. Prospective scope is these registered finite validation queries and controls, this recorded stack, dtype and threads. It does not establish every finite future input, cross-platform identity, improved biological accuracy or a scientific successor. Legacy multi-schedule interval intersection is a separate stronger property and cannot reject the possibility of matching one immutable vector.

6. **Custody and resources.** Root must bind postfreeze script/test hashes before execution. A supervising controller records stdout/stderr, command, cwd, exit code and pre/post hashes, enforces per-child wall and sampled RSS caps, and collects child-reported CPU and OS peak where available. Cumulative A CPU is the sum of child CPU plus controller CPU, with watchdog polling overhead included in controller CPU; per-child OS peak and sampled process-tree RSS are distinct fields. A cap/hash/access failure stops that process and the A suite, preserving completed records and the failed start. A numeric compatibility failure only records a candidate failure while the finite independent matrix continues.
